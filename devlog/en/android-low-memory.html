Investigating Android LOW_MEMORY exits in Zombie Stealth

DFD Lab · November 15, 2026

Zombie Stealth is a turn-based zombie stealth game for mobile. On Android, the game has been exiting around the point where the player enters the operating room. This post covers what the investigation has observed so far and where those observations stop.

What the OS recorded

In one recorded run, Android's low-memory killer terminated the game process, and the system's exit record for that launch gave the reason as LOW_MEMORY. This happened during app startup, before I had selected the operating room. The launch tool's "ok" meant Android reported that the activity had started, not that the game had rendered a frame.

That record shows how this one run ended. It doesn't account for every earlier exit.

A condition that was already present

Before the game launched, the device's SUnreclaim counter, which is the system's accounting of kernel memory it can't reclaim, was already high. It remained high after the game exited. A later snapshot, taken while the game wasn't running, showed a large nominal object capacity in the generic kmalloc-256 slab cache.

Neither measurement identifies an owner. The kmalloc-256 figure is an estimate of nominal capacity rather than measured use, and nothing here confirms a leak. This isn't evidence against the hardware, the OS or the graphics driver, and it doesn't clear the game either.

Why a later clean run isn't an answer

A later session completed a requested five-minute system trace, collecting system counter samples and app memory snapshots. The normal game screen was confirmed during the trace. This was system observation, not a five-minute playtest. No new LOW_MEMORY exit was observed, and the exit records before and after the trace were identical. Kernel memory pressure was also lower than during the earlier failure.

A run where the problem didn't appear, under milder conditions, isn't a fix. The trace didn't establish true peak memory usage, and it doesn't show that the game is stable.

Where things stand

The root cause is unresolved. I've paused the LOW_MEMORY investigation, and the issue remains open and unfixed. Work has resumed on environment art.
